# Инструкции для агента

## Перед изменением

1. Прочитай в `ARCHITECTURE.md` разделы **Source of Truth**, **Critical Invariants** и строку для типа задачи в **Where to change code**.
2. Прочитай указанные source-of-truth файлы и связанные тесты. Код и конфигурация важнее документации; о найденном расхождении сообщи в результате.
3. Проверь рабочее дерево. Не перезаписывай и не включай в свою задачу несвязанные пользовательские изменения.

## Неподвижные правила

- DevBoard превращает человеческий запрос в устойчивую задачу и отдаёт контекст агенту. Он не пишет код, не запускает Codex/Cursor и не создаёт pull request.
- Source of truth задачи — GitHub Issues в отдельном private-репозитории. Не заводи свою базу задач, workflow engine или аналог Jira.
- Вложения живут только в локальном `storage/`. Не коммить аудио, скриншоты, пользовательские файлы и `.env`.
- Транскрибация — только `gpt-4o-mini-transcribe`. Не подключай Whisper и не добавляй запасную модель без явной просьбы.
- Не печатай и не коммить секреты: `DEVBOARD_PASSWORD`, `DEVBOARD_SECRET_KEY`, `DEVBOARD_API_TOKEN`, `GITHUB_TOKEN`, `OPENAI_API_KEY`.
- Все текстовые файлы — UTF-8. Кириллицу не заменяй транслитом или Unicode-escape; JSON с текстом задачи пиши с `ensure_ascii=False`.
- Не добавляй микросервисы, Redis, Celery, WebSocket, OAuth, регистрацию пользователей, спринты и AI-оркестрацию, пока этого явно не попросили.
- DevBoard не зависит от NeuroROP и других рабочих репозиториев. Их код не импортировать.

## Рабочий процесс

1. Вноси минимальное изменение в существующую точку ответственности. Не дублируй маппинг задачи между API, CLI и frontend.
2. Если меняется HTTP-контракт, согласованно проверь `backend/main.py` и `frontend/src/api.ts`.
3. Если меняется смысл ID, статуса, проекта, приоритета или тела Issue, правь `backend/mapping.py` и его тесты.
4. `README.md` меняй только при изменении быстрого запуска. `ARCHITECTURE.md` — только при изменении устойчивого архитектурного факта.

## Проверка и завершение

- После изменения Python-логики: в `backend/` выполни `python -m pytest`.
- После изменения frontend: в `frontend/` выполни `npm run lint` и `npm run build`.
- После документации или любого изменения: проверь `git diff --check` и что затронуты только разрешённые файлы.
- Не называй задачу завершённой, пока не проверены затронутый контракт и релевантные команды. Явно укажи проверки, которые не запускались, и причину.
- Не запускай реальные GitHub/OpenAI вызовы без необходимости задачи.
